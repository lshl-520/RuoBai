# RuoBai 部署指南

这份文档给第一次部署的人看。按顺序做，不要把真实密钥提交到公开仓库。

> 提示：RuoBai 现在的主界面是 React 版（在 `frontend-react/` 目录）。
> 部署时需要先把 React 前端编译成静态文件，再由后端统一托管。
> 原版 HTML 已移到 `旧主题归档/legacy-html-3.13-20260803/public/`，目前只作为备用入口和对照资料保留。

## 零、最省事：Docker 一条命令部署

适合宝塔用户：先在宝塔软件商店安装 Docker，然后打开宝塔终端，粘贴下面这条命令。

把 `ruobai.example.com` 换成你自己的域名：

```bash
DOMAIN=ruobai.example.com bash -c "$(curl -fsSL https://raw.githubusercontent.com/lshl-520/RuoBai/main/scripts/install-docker.sh)"
```

脚本会自动完成：

- 拉取 GitHub 仓库代码。
- 生成 Docker 部署配置和随机数据库密码。
- 编译 React 前端。
- 启动 MariaDB 数据库容器。
- 启动 RuoBai 网站容器。
- 初始化数据库。
- 打印访问地址、后台地址、默认管理员账号和默认密码。

脚本默认只把网站暴露到服务器本机 `127.0.0.1:3000`，避免直接把 Node 服务暴露到公网。
宝塔里把你的域名反向代理到下面这个地址即可：

```text
http://127.0.0.1:3000
```

默认管理员：

```text
用户名：admin
密码：123456
```

后台入口：

```text
https://你的域名/admin
```

这个地址会自动进入 `https://你的域名/admin.html`。没有登录时，会先出现后台登录页。

第一次登录后必须立刻进后台修改默认密码。

如果想一起启动向量记忆容器，用：

```bash
ENABLE_VECTOR=1 DOMAIN=ruobai.example.com bash -c "$(curl -fsSL https://raw.githubusercontent.com/lshl-520/RuoBai/main/scripts/install-docker.sh)"
```

不熟悉 Docker 的萌新建议第一次先不要开向量记忆。先让网站跑起来，再做长期记忆。

Docker 模式以后更新代码，也重新运行同一条命令。后台里的“网站更新”会提示 Docker 部署模式，不会执行 git/pm2 更新。

如果你要在同一台服务器上做第二套测试安装，不要直接重复用默认配置。换掉安装目录、端口和 Docker 项目名，避免影响正式站点：

```bash
COMPOSE_PROJECT_NAME=ruobai_test INSTALL_DIR=/www/wwwroot/ruobai-test APP_PORT=3001 DOMAIN=test.example.com bash -c "$(curl -fsSL https://raw.githubusercontent.com/lshl-520/RuoBai/main/scripts/install-docker.sh)"
```

## 一、服务器准备

需要准备：

- Node.js 20 或更新版本。
- MariaDB 或 MySQL。
- 一个域名。
- pm2（让后端长期在后台运行）。
- 可选：Docker（只有想启用「向量记忆」功能才需要，见第六节）。

## 二、拉取代码

```bash
git clone https://github.com/lshl-520/RuoBai.git
cd RuoBai
```

## 三、安装依赖

后端依赖：

```bash
cd server
npm install
cd ..
```

前端依赖：

```bash
cd frontend-react
npm install
cd ..
```

## 四、配置后端

复制配置样例：

```bash
cd server
cp .env.example .env
```

修改 `server/.env`，至少填好：

```env
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=你的数据库密码
DB_NAME=ruobai
SESSION_SECRET=换成一串很长的随机字符
PORT=3000
CORS_ORIGINS=https://你的域名,https://www.你的域名
BETA_REGISTRATION_ENABLED=true
OPEN_SOURCE_SINGLE_USER=false
```

`server/.env` 是本机私密配置，不要提交到 git。

## 五、初始化数据库

```bash
cd server
node init-db.js
cd ..
```

这一步会建好所有数据表（用户、角色、消息、记忆、动态等）。

## 六、编译 React 前端

回到项目根目录，编译前端：

```bash
cd frontend-react
npm run build
cd ..
```

编译产物会生成在 `frontend-react/dist/`。
按你的反向代理配置，把这个目录作为站点根目录，或让 Web 服务器指向它。

## 七、启动后端服务

本地试运行：

```bash
cd server
npm start
```

服务器长期运行（推荐 pm2）：

```bash
cd server
pm2 start ecosystem.config.js
pm2 save
```

## 八、反向代理

用 Nginx（或宝塔面板）配置站点：

- 静态文件：站点根目录指向 `frontend-react/dist/`。
- 接口转发：把 `/api` 和 `/user_assets` 的请求转发到本机 `3000` 端口。
- 开启 HTTPS。

完成后访问你的域名，检查首页能否打开、能否注册登录。

## 八点五、`user_assets` 必须跨版本共享（升级时最容易踩的坑）

用"新建 release 目录 + 切换"的方式升级时，**`user_assets` 不能每个版本各留一份**。

原因：后端的 `/user_assets` 是 `express.static(projectRoot/user_assets)`，`projectRoot` 就是**后端进程当前所在的那个目录**。如果你把新版本解压到一个新目录、再切换过去，而 `user_assets` 没有跟过去，那么：

- **聊天图片、角色立绘、Live2D 模型、语音缓存会全部 503**（表现为：动态页图片空白、Live2D 加载不出来、立绘变破图）
- 更糟的是，**新版本运行期间新生成的图片会写进新目录**，下次再发布又留在旧目录里，越积越散

正确做法是把真实文件放在一个**固定位置**，每个版本目录里只放一个指向它的符号链接：

```bash
# 真实资源放在固定目录（只此一份）
STORE=/srv/ruobai/user_assets
mkdir -p "$STORE"

# 每个版本目录里建软链，而不是复制
ln -s "$STORE" /srv/ruobai-release-<版本>/user_assets
```

这样资源只存一份，读写都跟随软链，发布多少次都不会丢。

如果你已经踩了这个坑（资源散在多个旧版本目录里），先归集再改软链——`cp -a --backup=numbered -n` 只新增、同名冲突自动改名，不会覆盖已有文件：

```bash
for old in /srv/ruobai-release-*/user_assets; do
  [ -L "$old" ] && continue          # 已是软链就跳过
  cp -a --backup=numbered -n "$old/." "$STORE/"
done
```

归集后建议逐对校验（确认旧目录里的每个文件在仓库中都能找到且内容一致），再把各版本目录的 `user_assets` 换成软链。

> 发布新版本前的自检：确认新版本目录里的 `user_assets` 是指向共享仓库的软链，而不是新拷贝的一份。

## 八点六、编译前端时必须注入 Live2D Cubism Core 地址

角色要"动起来"（Live2D）需要 Live2D 官方的 Cubism Core。这个地址是**编译时**注入的：

```bash
# frontend-react/.env.local（此文件被 .gitignore 忽略，不会进仓库）
VITE_RUOBAI_LIVE2D_CORE_URL=/user_assets/live2d-runtime/cubism-5.1.0/live2dcubismcore.min.js
```

**如果不设这个变量，编译出的前端里地址是空的**，运行时会直接报 `未配置 Live2D Cubism Core`，模型加载在约 100 毫秒内失败并回退成静态预览图 —— 表现就是**角色立绘能显示，但完全不会动**。

> 这一步特别容易漏：因为 `.env.local` 被 git 忽略，用"导出干净源码再编译"的方式发布时它不会跟过去。**编译前先确认该文件存在且变量非空。**

把 Core 放在自己的服务器上（而不是引用官方 CDN）的好处是不依赖外网，地址与 `user_assets` 一样**跨版本共享**：

```bash
# 目录示例（放在共享仓库里，各版本共用）
user_assets/live2d-runtime/cubism-5.1.0/live2dcubismcore.min.js
```

编译后自检（两条都要过）：

```bash
# 1. 产物里必须有 Core 地址
grep -c 'live2d-runtime/cubism' dist/assets/index-*.js      # 期望 >= 1

# 2. 产物里不应该引用官方 CDN（用自托管时）
grep -c 'cubism.live2d.com' dist/assets/index-*.js          # 期望 0
```

> 另外注意：如果只想临时救急，也可以在站点 `index.html` 里写一行
> `<script>window.__RUOBAI_LIVE2D_CORE_URL__="/user_assets/.../live2dcubismcore.min.js";</script>`
> —— 运行时会优先读这个全局变量。但这只是临时手段，**下次发布覆盖 `index.html` 就失效了**，正式做法仍是写进编译变量。

## 八点七、手机 App：Android 15+ 必须自己避让系统栏

Android 15 起，`targetSdk` 35+ 的应用会被系统强制 **edge-to-edge**：状态栏和导航栏不再占用布局空间，而是**浮在页面之上**。

如果你的网页没有自己避让，手机上会看到：**顶部标题被状态栏压住、底部标签栏被导航栏盖住**。

CSS 里用安全区自行避让即可（本项目已内置，新增固定顶栏/底栏时照做）：

```css
:root {
  --rb-safe-top: env(safe-area-inset-top, 0px);
  --rb-safe-bottom: env(safe-area-inset-bottom, 0px);
}
.app-shell { padding-top: var(--rb-safe-top); }                     /* 顶部让开状态栏 */
.bottom-nav { height: calc(76px + var(--rb-safe-bottom)); }         /* 底部给手势条留高度 */
```

> **本机浏览器验证不出来**：电脑上的 Chrome 没有系统栏，安全区是 0，看起来一切正常。**这个问题只能在真机上验收。**

## 八点八、私有关系配置（哪些东西不该进仓库）

角色怎么称呼对方、对方怎么称呼她 —— 这属于**部署方自己的关系**，不应该写死在公开仓库里。

项目把这类内容抽成了一层**可选的私有配置**：

| 层 | 内容 | 在哪 |
|---|---|---|
| 公开默认值 | 通用称呼（宝 / 宝宝 / 老婆 / 宝贝…） | 代码里，任何部署直接可用 |
| 私有覆盖 | 你自己的称呼（如"心宝"）与关系设置 | 你自己的机器，不进仓库 |

**机制**：`server/xiaobai-core.js` 启动时按以下顺序找配置，**找不到就用默认值，不会报错、不影响启动**：

1. 环境变量 `XIAOBAI_PRIVATE_CONFIG` 指定的绝对路径
2. `server/user_assets/private/xiaobai-private.json`

配置格式（只写你要覆盖的字段即可，缺的自动用默认值）：

```json
{
  "relationship": {
    "petNames": ["宝", "宝宝", "老婆", "亲爱的", "心宝", "宝贝"],
    "praiseNames": ["你", "老婆", "宝宝", "宝贝"],
    "intimateNames": ["老婆", "宝宝", "宝", "亲爱的"],
    "praiseNamesShort": ["你", "老婆"],
    "thanksForPetNames": ["谢谢你", "谢谢宝", "谢谢老婆", "有你真好"]
  }
}
```

> **`intimateNames` 故意不含泛指的「你」**：它用于判断「亲密称谓 + 求教」这种唯一指向的组合，
> 带上「你」会把「我不会，你能不能一步步教我」这种普通提问误判成性需求。

**⚠️ 必须确认这个文件不会进仓库**（本项目已在 `.gitignore` 兜住，自建部署请自查）：

```bash
git check-ignore -v server/user_assets/private/xiaobai-private.json
# 有输出 = 已被忽略，安全；无输出 = 会被提交，立刻加 .gitignore 规则
```

> 踩过的坑：`.gitignore` 里的 `user_assets/*` **只匹配仓库根目录**。
> 后端工作目录是 `server/`，所以 `server/user_assets/` 必须单独加一条规则兜住，
> 否则私有配置会被 git 收走 —— 这正是本项目真实发生过的事故。

## 九、向量记忆（可选，让角色记住长期对话）

这是进阶功能。不配置也能正常聊天，只是角色只能看到最近的消息，
配置之后角色能从全部历史记录里按语义找回相关回忆。

需要 Docker。启动两个容器：

```bash
# 1. 向量数据库 Qdrant
docker run -d --name ruobai-qdrant \
  -p 6333:6333 \
  -v ruobai_qdrant_storage:/qdrant/storage \
  qdrant/qdrant

# 2. 中文向量模型服务（把对话转成向量）
docker run -d --name ruobai-embedding \
  -p 8090:80 \
  ghcr.io/huggingface/text-embeddings-inference:cpu-1.6 \
  --model-id BAAI/bge-small-zh-v1.5 --port 80
```

后端会自动连接这两个服务（默认地址 `127.0.0.1:6333` 和 `127.0.0.1:8090`）。
如果地址不同，在 `server/.env` 里覆盖：

```env
VECTOR_QDRANT_URL=http://127.0.0.1:6333
VECTOR_EMBEDDING_URL=http://127.0.0.1:8090
VECTOR_EMBEDDING_MODEL=BAAI/bge-small-zh-v1.5
VECTOR_COLLECTION=ruobai_memories_local
```

说明：

- 两个容器没启动时，聊天功能不受影响，只是没有「长期记忆检索」。
- 向量数据存在 Docker 数据卷里，不会丢。
- 首次需要把历史对话导入向量库后才会生效（导入脚本在 `server/vector-memory/` 下）。

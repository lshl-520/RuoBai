  - React 主框架

## 2. 为什么这样定

原因不是“技术圈都说 React 好”，而是下面这几件事同时成立：

- 用户不懂代码，需要后续 AI 更容易接手
- React 生态更适合长期组件化维护
- 未来如果要做双主题、统一页面骨架、轻动画，React 更顺手
- 当前线上 `https://lshl.fun/` 已经在用，不能为了重构把现有可用版本搞坏
- 用户对“坏了自己没能力修”的风险承受能力很低，所以必须走稳路

这次路线的核心不是“最快”，而是：
**可回退、可接力、不会把她搞丢。**

## 4. React 主线内部怎么设计

### 4.1 页面骨架只保留一套

以后真正开发的页面只写一遍，不再出现：

- HTML 一套聊天室
- Vue 一套聊天室
- React 再一套聊天室

以后应该是：

- React 版聊天室这一套

同理适用于：

- 首页
- 登录页
- 聊天列表
- 聊天室
- 角色页
- 动态页
- 记忆页
- 我的页

### 4.2 主题只控制外观，不控制功能

主题负责：

- 颜色
- 字体
- 圆角
- 阴影
- 留白
- 按钮气质
- 页面氛围
- 轻动画风格

主题不负责：

- 消息怎么发
- 登录怎么提交
- 数据怎么取
- 动态怎么加载
- 角色怎么保存

一句话：
**功能是身体，主题是衣服。**

### 4.3 两套主题怎么定位

- `微光`
  - 默认主题
  - 以后默认截图、默认展示、默认 git 主线视觉都以它为准

- `原版`
  - 第二主题
  - 保留现在开源版那种熟悉感觉
  - 给喜欢旧味道的人切换用

以后统一口径：

**若白 React 主前端，默认微光主题，内置原版经典主题。**

## 5. React 第一批先做什么

React 主线第一批不要一上来全站重做。

建议顺序：

1. 首页 / 登录页
2. 聊天列表 / 聊天室
3. 角色页
4. “我的”页基础版
5. 动态 / 记忆
6. 高级功能和管理区

### 第一批为什么只抓这几块

因为它们：

- 最能体现新主线有没有长对
- 最能体现微光主题是不是接近用户心里的 UI
- 最能尽快给用户看到“不是空转，真的有新成果”

### 第一批先不重做什么

先不重点处理：

- 动态页复杂交互
- 记忆页深度功能
- 管理页大改
- 实时通话
- 发图主链
- 重型模型接入重构

原因不是它们不重要，而是：
**不适合拿来当 React 主线起步页。**

## 6. GSAP 的定位

GSAP 可以纳入 React 主线，但不是第一阶段重点。

### 当前定位

**微光主题的轻动画加分项**

### 第一阶段适合用在哪

- 页面淡入淡出
- 卡片轻微上浮
- 按钮点击反馈
- 抽屉 / 弹窗出现
- 聊天气泡进入动画
- Hero 区轻微呼吸感
- 主题切换时的柔和过渡

### 现在先别碰什么

- 很重的滚动联动特效
- 大量全屏视差
- 复杂 3D 动效
- 会影响聊天输入稳定性的动画
- 会影响消息流稳定性的动画

一句话：
**先让她变柔和，不要先让她变炫。**

## 7. 正式开工前必须先做的安全动作

React 主线还没开工前，必须先做下面这些。

### 7.1 整仓安全备份

需要两层：

- Git 分支安全点
- 本地物理备份包

原因：
Git 适合回代码，本地完整备份更能给用户安全感。

### 7.2 打一个 React 开工前冻结点

它的作用是：
明确哪一刻开始，旧 HTML / Vue / React 三者身份正式分开。

### 7.3 建立正式主线说明文件

这份文档本身就是第一份正式说明。

以后如果还要补一个更适合新对话复制的版本，
可以在本地管理目录再做一份“React 主线交接提示词”。

### 7.4 建立阻塞小本本

专门记录：

- 暂时搞不定的问题
- 不确定但不能猜的问题
- 风险高、必须停下的问题
- 以后需要 Claude 外援的问题

作用：
**不让问题消失在对话上下文里。**

### 7.5 先定禁止事项

正式开工前就写死：

- 不改线上 `lshl.fun`
- 不碰生产数据库
- 不拿本地继续做日常聊天
- 不在 Vue 版继续追加开发
- 不在 `public/` 做大规模重构
- 不一上来做重动画和大特效

### 7.6 每一步都带验证

以后推进节奏固定成：

- 做一点
- 验一点
- 记一点
- 再往下走一点

不能靠“感觉差不多”。

## 8. 过渡期工作纪律

过渡期统一遵守这 4 条：

- 不在 `src-vue/` 追加新功能
- 不在 `public/` 做大规模视觉重构
- 新的正式前端页面一律落到 React 主线
- 如果为了对照旧逻辑必须看 HTML/Vue，只看，不顺手继续在那里开发

目的：
避免“三套一起继续改”的混乱。

# RuoBai V2.0 Design System 建设计划

> 状态：Phase 0 设计方向确认稿
> 日期：2026-07-30  
> 当前边界：只做现状分析与设计规划，不修改 React、业务功能、接口或数据库。

## 1. 结论

若白不需要推翻微光 2.0。现有界面已经形成了可识别的品牌雏形：暖米白纸面、克制的脏粉、薰衣草微光、角色立绘、较安静的留白，以及“她一直在”的文字语气。

当前缺少的不是另一套新皮肤，而是把这些优点整理成一套可以重复使用、可以解释、能覆盖所有状态和桌面/手机尺寸的正式规则。

正式工作流：

1. `新思维's team` 教育版 Figma 是唯一正式设计中心和最终视觉来源。
2. Pencil 只做快速布局和视觉探索。
3. Open Design 只做独立提案和交互验证。
4. Codex 负责项目盘点、规范整理、Figma 协作、设计审查，以及设计确认后的 React 实现。
5. 任何来自 Pencil、Open Design 或旧 UI 图片的想法，只有进入 Figma 正式文件后才算被采用。

## 2. 微光 2.0 现状审计

### 2.1 值得保留

- **品牌色已经有基础**：`#faf6f2` 暖米白、`#c16579` 脏粉、`#9a8fc0` 薰衣草、`#d2906f` 陶土暖色和 `#6fae8e` 鼠尾草绿，比通用粉紫 AI 页面更安静，也更适合长时间聊天。
- **角色存在感明确**：头像、立绘、关系文字、聊天背景中的角色形象，让若白不像一个只有文本框的普通聊天工具。
- **聊天页是最接近核心体验的页面**：消息层级清楚，语音、图片、模型、实时通话和输入入口已经围绕真实功能组织。
- **角色页是当前最成熟的视觉样板**：主陪伴大图和其他角色卡片有明显层级，也能体现“每段关系分别保存”的产品特点。
- **文字语气有若白自己的温度**：如“随时可以说话”“她们各自记得关于你的事”，比通用后台式标题更符合陪伴产品。
- **已有无障碍意识**：部分图片按钮有聚焦样式，部分动画支持“减少动画”，可继续扩展，而不是从零开始。

### 2.2 当前主要问题

#### P0：影响整体产品结构

- **桌面应用不是正式桌面布局**：主应用固定最大宽度 480px，在宽屏中只是居中的手机版，两侧长期空白；桌面没有自己的导航、内容宽度和信息组织规则。
- **设计变量不完整**：已有颜色、阴影、圆角和动画时长，但缺少正式的字号层级、间距语义、图标尺寸、模糊层级、透明度、层级顺序和断点规则。
- **同类规则散落**：6 个 CSS 文件约 2857 行，存在约 372 处直接写死的颜色、249 处圆角和 85 处动画声明。新页面容易继续创造新的颜色、圆角和动效。
- **页面视觉浓度不一致**：官网首页像品牌展示页，角色页偏视觉海报，聊天列表和设置页偏轻量工具，动态页又大量依赖背景图，缺少同一套页面骨架。
- **状态没有形成统一语言**：加载、空白、失败、断网、权限拒绝、发送中、禁用和重试没有统一组件和表达方式。

#### P1：影响清晰度与长期使用

- **部分页面对比度过低**：动态空状态和加载中的设置页接近整页发白，背景图、正文和操作入口难以辨认。
- **圆角和卡片使用过多且层级不稳定**：卡片、按钮、头像、输入框分别出现多种接近但不一致的圆角，难以判断哪些是同类组件。
- **动画有数量、没有语义**：目前动画声明较多，但尚未说明什么场景应该淡入、上移、呼吸或完全不动。
- **桌面与手机共用同一壳但没有响应式职责**：手机表现基本可用，桌面却没有利用更宽空间；不能简单把手机界面等比放大。
- **关系数字需要产品解释**：关系温度、亲密度等数据如果保留，必须说明来源、变化原因和用户能否关闭；不能仅作好看的假数字。

### 2.3 不应照抄 ChatGPT 建议的部分

- 不直接采用示例中的奶白、浅粉、淡紫色值。现有微光色更有辨识度，应先做对比度测试再调整。
- 不把“现代玻璃拟态”设为总方向。玻璃只能用于导航、浮层或少量强调，不能让所有内容都变成半透明卡片。
- 不先在 Pen 建正式组件。正式变量、组件和页面全部进入 Figma；Pen 只保留探索稿。
- 不先画一个包含天气、音乐、今日状态等新功能的首页。设计阶段不能用新功能填满版面。
- 不机械地把 Welcome 首页排在第一。官网当前已有较完整品牌视觉，最应先统一的是用户每天使用的应用外壳、聊天室和聊天列表。

## 3. RuoBai Design System 1.0 方向

### 3.1 品牌定义

**核心承诺**：她记得、她回应、她一直在。

**视觉关键词**：温柔、安静、长期陪伴、生活感、轻盈、可信、有人味。

**要保留的识别信号**：

- 暖米白底色；
- 克制的玫瑰粉和薰衣草色；
- 角色头像与立绘；
- 少量宋体用于情绪标题和引语；
- 柔和但清晰的层级；
- 陪伴式中文文案。

**禁止方向**：

- 赛博朋克、科技蓝控制台、游戏大厅；
- 高饱和霓虹、满屏粉紫发光；
- 每个区域都做玻璃卡片；
- 订阅、排行榜、关注量等不存在的商业或社交功能；
- 为好看而展示来源不明的亲密度、温度和统计；
- 用整张生成图片冒充可编辑页面与真实交互。

### 3.2 Foundations / 设计变量

第一版必须建立以下变量，并为每项写清使用场景：

- **颜色**：背景、表面、文字、边框、品牌强调、AI 强调、成功、警告、错误、信息、遮罩和反色文字。
- **字体**：展示标题、页面标题、区块标题、正文、聊天正文、辅助文字、按钮文字和数字；同时定义字号、字重、行高。
- **间距**：以 4 为基础，但命名按用途，例如紧凑、组件内、卡片内、区块间、页面边距，不让页面直接随意挑数字。
- **圆角**：输入/小控件、按钮/普通卡片、大媒体卡片和完整圆形四类即可，避免为每个组件新增圆角。
- **阴影与边框**：普通表面、悬浮表面、弹窗和品牌强调；优先用轻边框建立层级，减少所有卡片都投影。
- **模糊与透明度**：只用于导航、遮罩和浮层，正文承载面保持清楚。
- **动效**：即时反馈、普通切换、弹窗进入和情绪氛围四级；补齐“减少动画”模式。
- **尺寸**：图标、头像、触控目标、输入框高度和导航高度；所有触控目标不小于 44px。
- **响应式**：手机、平板/窄桌面、宽桌面三档。具体断点在首批原型中验证后锁定。

### 3.3 基础组件

组件不能只画默认外观，每个组件至少覆盖：默认、悬停（桌面）、按下、聚焦、禁用和加载；涉及数据时还要有成功与失败。

- Button：主要、次要、文字、危险、图标按钮。
- Input：普通输入、搜索、聊天输入、多行输入、密码、语音状态。
- Avatar：用户、角色、在线、生成中、加载失败。
- Card：列表项、媒体卡、记忆卡、设置行；避免把所有区块都做成卡片。
- Bubble：AI、用户、语音、图片、表情、系统提示、发送中、失败重试。
- Navigation：手机底部导航、桌面侧栏、页面头部、返回与二级导航。
- Feedback：页面内错误、Toast、确认框、底部面板、加载骨架、空状态、断网页。
- Controls：开关、单选、复选、滑杆、分段选择、标签和菜单。

### 3.4 陪伴产品专属模式

通用组件之外，若白必须建立自己的模式组件：

- 角色状态与角色切换；
- 关系摘要及其来源说明；
- 记忆“为什么保存 / 为什么想起 / 如何纠正”；
- 动态、点赞、评论与进入聊天的连续流程；
- 模型不可用、语音不可用和图片生成失败时的降级；
- 麦克风、相册、通知等权限说明；
- 主动消息、勿扰和用户可停止的边界；
- 数据导出、恢复与删除确认；
- 私密内容在锁屏、通知和截图中的保护规则。

若白目前由个人长期维护，第一阶段不同时铺开三份大型文件。先把唯一设计系统文件做完整，等基础组件和前三个核心原型稳定后，再建立产品页面文件；这样既符合正规产品工作流，也不会增加无意义的维护负担。

## 5. 第一批页面顺序

### P0：先建立每天都会用到的核心骨架

1. **App Shell**：手机底部导航、桌面侧栏、页面头部、内容宽度和滚动规则。
2. **Chat Room**：普通文字、长文本、语音、图片、思考中、输入中、发送中、失败、断网和权限拒绝。
3. **Chat List**：有角色、无角色、加载、搜索、未读和模型不可用。
4. **Characters**：以现有角色页为视觉样板，梳理主陪伴、普通角色、创建、编辑和删除恢复。
5. **Moments + Comments**：列表、空状态、评论展开、输入、发送中、成功、失败和进入聊天。

### P1：补齐长期关系与配置

6. Memory + Chat History。
7. Profile / Settings / Model Configuration。
8. Auth + First Run Onboarding。
9. Realtime Call 全屏状态与权限状态。

### P2：品牌与低频页面

10. Welcome 官网首页。
11. 隐私、协议、导出恢复和其它低频管理页。

这样排序不是说官网不重要，而是官网已经有相对完整的视觉；若白当前最明显的不一致发生在登录后的高频体验。

## 6. 执行顺序与验收门槛

1. 将现有桌面、手机和关键状态截图放入 `00 Audit & Legacy`，只做标注，不美化。
2. 在 `01 Design System` 建立品牌原则和基础变量，先验证文字对比度与长时间阅读舒适度。
3. 完成 Button、Input、Avatar、Navigation、Bubble 和 Feedback 六组 P0 组件及所有状态。
4. 用这些组件完成 App Shell、Chat Room 和 Chat List 手机/桌面原型。
5. 经过一次设计审查后再扩展 Characters 与 Moments + Comments。
6. 只有进入 `Ready for Development` 页面并标明版本的设计，才可以交给 Codex 修改 React。
7. React 实现后必须回到 Figma 对照桌面和手机截图，差异记录在设计文件的 Changelog。

第一阶段完成标准：

- 没有修改 React、CSS、接口或数据库；
- Figma 正式文件全部位于 `新思维's team` 教育团队；
- 新页面不包含不存在的功能和假数据；
- 每个 P0 组件都有交互和异常状态；
- 手机与桌面不是简单缩放关系；
- 颜色、文字和触控尺寸通过基本可读性检查；
- 下一位 AI 不需要重新猜若白的视觉方向和工具职责。

## 7. Phase 0 拍板清单

进入 Figma 正式建设前，只需要确认下面六件事：

1. **不推翻微光 2.0**：保留暖米白、脏粉、薰衣草、陶土色、鼠尾草绿、角色形象和陪伴式中文文案。
2. **整体升级方向**：背景和长文本以安静中性色承载，粉色和紫色只用于品牌强调；减少满屏发光、玻璃和层层卡片。
3. **先解决高频体验**：第一批页面顺序为 App Shell、Chat Room、Chat List、Characters、Moments + Comments，不先重画官网。
4. **先建六组 P0 组件**：Button、Input、Avatar、Navigation、Bubble、Feedback；每组都必须包含交互、加载和失败状态。
5. **不加入假功能**：不为填版面增加天气、音乐、订阅、排行榜、关注量或来源不明的关系数字。
6. **设计确认前不改 React**：只有进入 `Ready for Development` 并标明版本的设计，才允许交给 Codex 开发。

## 8. 当前进度与下一步

2026/7/30，用户已确认 Phase 0 的六条拍板清单，Phase 1 Foundations 与 Phase 2 File Structure 也已完成并通过逐页截图验收。正式文件现有 10 个页面目录、4 个变量集合、121 个变量、8 个文字样式和 4 个阴影样式；54 条模式别名均有效，封面、品牌、颜色、字体、尺寸和阴影文档无明显裁切或溢出。

下一步进入 Phase 3，按 `Button → Input → Avatar → Navigation → Bubble → Feedback` 的顺序一次只制作并验收一个组件族。每个组件开始前重新搜索可复用设计库，所有颜色、间距、圆角和尺寸绑定现有变量；六组基础组件完成前不创建完整产品页面，也不修改 React。

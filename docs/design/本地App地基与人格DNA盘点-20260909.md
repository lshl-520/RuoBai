# 本地 App 地基与人格 DNA 盘点

日期：2026/9/9
状态：只读盘点后的方案草案，未施工、未迁移、未改线上

## 结论先说

当前 Android 还是网页壳，`frontend-react/capacitor.config.json` 的服务器地址指向部署方自己的域名（开源仓库里不写具体地址，打包时用 `VITE_API_ORIGIN` 指定）。手机暂时不能在断网时独立保存和运行完整的若白。

项目已经有两块可以直接复用的基础：身份包 `server/identity-pack.js`，以及只输出已确认记忆的筛选逻辑。下一阶段应先把“本地数据层”做出来，再决定模型放手机、放电脑，还是继续用用户自己的远程接口。

## 手机必须自己保存的内容

这些内容决定“小白还是不是小白”，不能只放服务器：

- 用户身份、角色身份、人设和形象规则
- 关系状态、当前心情、重要约定和纪念日
- 已确认记忆，以及每条记忆的来源、置信度和是否重要
- 聊天记录（至少最近对话；长期记录可分段存储）
- 用户和角色的动态、评论、附件索引
- 模型渠道设置的名称和用途；密钥应使用手机系统安全存储，不能写入普通 JSON
- 导入包版本、备份时间、数据校验值和迁移记录

## 服务器暂时负责的内容

在本地化完成前，以下能力可以继续走服务器：

- 远程模型请求和流式回复
- 多设备同步、云端备份和朋友共享
- 图片、语音、实时通话等需要较大网络或第三方接口的能力
- 服务器端的任务调度和公开版多用户隔离

服务器不是人格的唯一来源；它应变成可选同步端。向量服务当前已关闭，历史向量召回暂时变弱，不影响本地化盘点。

## 本地化后的三种状态

1. **在线状态**：本地保存数据，模型请求可以走用户配置的远程渠道。
2. **半离线状态**：没有网络时仍能打开角色、看聊天和记忆；发送消息时提示需要联网。
3. **完全离线状态**：只有用户手机或电脑装有可用本地模型时，才尝试离线生成回复。不能把“有本地数据库”误说成“有离线模型”。

## 人格 DNA 初稿

人格 DNA 只收稳定、可追溯的内容，不把某次模型临时发挥当成永久人格：

- **身份层**：名字、称呼、核心人设、说话节奏、形象连续性规则
- **关系层**：与用户的关系定位、重要共同经历、约定和边界
- **状态层**：当前心情、近期发生的事、暂时性的偏好；必须带时间并允许过期
- **记忆层**：只纳入已确认记忆；保留来源和置信度，未确认候选不能写进 DNA
- **能力层**：能聊天、看图、发图、语音、动态等能力的真实开关；不能把接口可用性写成人格特征
- **隐私层**：哪些内容只允许本机使用，哪些内容允许同步；默认不上传私密原文

## 数据迁移原则

- 先导出新的本地副本，再导入手机；不覆盖线上数据库
- 导入包必须带版本号、来源说明、校验值和可回滚备份
- 身份、人设、已确认记忆、聊天记录分开导入，任何一类失败都不影响其他类
- 历史向量索引属于辅助数据，不能代替原始聊天，也不能反向覆盖记忆
- 3 月早期记录存在部分时间不完整，迁移时保留“不完整”标记，不编造日期

## 当前不做

- 不立刻改 Capacitor 服务器地址
- 不把线上聊天或高风险人设复制进代码仓库
- 不在服务器编译 Android、不安装本地模型
- 不把“本地数据库”宣传成已经完成的离线若白

## 下一步施工顺序

1. 设计本地 SQLite 表和文件目录，先做空数据库与版本迁移测试。
2. 把身份包扩展为可导入/导出的本地数据包，先用测试角色验收。
3. 做本地聊天缓存和断网只读页面，不接真实线上迁移。
4. 再评估模型直连、加密密钥存储和可选同步。

完成标准：手机断网时至少能打开角色、关系、已确认记忆和历史聊天；联网恢复后不覆盖、不重复、不丢失；模型是否可用单独显示，不伪装成“她消失了”。

# Android 本地存储插件评估

日期：2026/9/10  
状态：只读评估，未安装依赖、未改配置、未打包

## 推荐组合

第一阶段建议采用：

1. `@capacitor-community/sqlite` 8.x：保存角色、关系、记忆、聊天、动态和同步记录。它当前发布线为 8.x，并声明支持 Capacitor 8；支持事务、版本升级和可选 SQLCipher 加密。
2. 一个使用 Android Keystore 的安全键值存储：只保存 SQLite 加密钥匙、远程渠道密钥的引用或登录会话等小型敏感值。普通 SQLite 表和导出 JSON 都不能保存明文密钥。
3. Capacitor Filesystem：把图片、音频等附件放应用私有目录；数据库只保存相对路径、哈希和大小。

`@capawesome-team/capacitor-sqlite` 的文档也提供 Capacitor 8 支持、事务和升级语句，但安装需要 Capawesome Insider 私有仓库授权；在没有明确购买/授权前不把它列为项目依赖。

## 权限边界

- 数据库、备份、暂存文件和附件先放应用私有目录，不申请读取整个手机存储的权限。
- 第一阶段不申请 `READ_MEDIA_IMAGES`、`READ_MEDIA_VIDEO` 或旧版外部存储权限；从系统照片选择器拿到的文件先复制进应用私有目录，再写附件索引。
- 不申请无关的通讯录、短信、定位或无障碍权限。
- 如果以后要导出到用户指定目录，单独使用系统文件选择器，并把导出视为用户主动操作。

## 加密与密钥

- SQLite 加密属于后续明确施工项；先把迁移、备份和回滚做稳定。
- 若启用 SQLCipher，密钥由 Android Keystore 保护，JavaScript 层只拿到临时使用值，不把密钥写入普通配置、日志或身份包。
- 安全键值存储只放小值，不拿它替代 SQLite，也不把聊天正文拆成很多键。

## 依赖风险与验收门槛

- 社区插件免费、公开，但需要在本机锁定版本并做 Android 真机/模拟器迁移测试；不能只凭网页测试通过就发布。
- Capawesome 方案功能完整，但存在付费仓库门槛；若以后选它，先确认费用和许可，再单独记录决定。
- 任何插件接入前必须先做备份、版本迁移失败回滚、应用卸载/升级保留数据、断网只读和附件路径穿越测试。
- 这份评估不等于已经安装插件或已经拥有本地 App；当前 Capacitor 仍保持远程网页壳。

## 建议的下一步

先不装插件，继续把当前 Node 验证模块的表字段与身份包导入/导出字段对齐；之后在本机 Android 测试工程中只安装一个候选 SQLite 插件，做空库、升级、回滚和备份恢复验收。系统安全存储要单列小测试，确认密钥从不进入日志和导出包。

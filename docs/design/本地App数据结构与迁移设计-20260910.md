# 本地 App 数据结构与迁移设计

日期：2026/9/10  
状态：本机设计完成，尚未接入 Android，尚未迁移线上数据

## 这一步要解决什么

先把“关机后仍在手机里”的数据边界定清楚。SQLite 只保存若白的身份、关系、已确认记忆、聊天和附件索引；模型密钥不进数据库，线上数据也不在这一步导入。

## SQLite 表（第一版空库）

| 表 | 保存什么 | 关键边界 |
|---|---|---|
| `app_meta` | 本地库版本、安装实例、最近备份时间、数据校验值 | 只保存元数据，不放密钥 |
| `characters` | 角色身份、人设、形象规则、头像引用、当前心情和亲密度 | `remote_id` 可为空，本地编号不依赖线上编号 |
| `character_runtime` | 关系状态、当前状态、更新时间 | 一名角色一行，按本地角色编号关联 |
| `memories` | 记忆内容、类型、来源、置信度、重要程度、确认状态 | DNA 和聊天上下文只读取已确认记录；候选不升级 |
| `messages` | 聊天消息、发送者、时间、媒体引用、同步状态 | 使用本地消息编号；线上编号只是可选映射 |
| `moments` | 动态正文、角色归属、可见范围、时间、同步状态 | 不自动把用户分享升格为长期记忆 |
| `moment_comments` | 动态评论及角色/用户来源 | 只关联本地动态，不跨用户复用 |
| `attachments` | 图片、音频等文件的相对路径、哈希、类型和大小 | 数据库不存二进制；路径不能指向仓库或高风险目录 |
| `sync_journal` | 导入/同步批次、对象类型、对象编号、操作和结果 | 用于避免重复、覆盖和无法解释的冲突 |

模型渠道只在 `app_meta` 或单独的非敏感配置中保存名称、用途和系统密钥存储引用；真正的密钥只能放手机系统安全存储。

## 手机文件目录

```text
应用私有目录/
├─ data.sqlite                 # SQLite 主库
├─ attachments/
│  ├─ original/                # 原图、原音频
│  ├─ thumbnail/               # 可重建缩略图
│  └─ pending/                 # 未完成导入，成功后再归位
├─ exports/                    # 用户主动导出的本地包
├─ backups/                    # 迁移前自动备份，保留最近几份
└─ temp/                       # 可随时清理的临时文件
```

导出包与备份包必须带版本号、来源、生成时间和校验值。任何导入先写入 `temp` 暂存库并校验，成功后再合并；失败只删除暂存库，不碰现有本地库。

## 版本迁移规则

1. 通过 SQLite `PRAGMA user_version` 判断版本，迁移必须按 `1 → 2 → ...` 顺序执行。
2. 迁移开始前复制数据库和附件清单到 `backups/`，并记录批次号。
3. 每个版本在一个事务中执行；失败就回滚事务并保留备份，不继续下一版本。
4. 第一版只允许新增表、字段或索引，不做自动删表、删字段、覆盖正文。
5. 迁移完成后重新计算库内对象清单校验值，写回 `app_meta`；校验不一致视为失败。
6. 线上编号只做映射，不能拿线上编号直接覆盖本地对象；冲突进入 `sync_journal` 等待明确处理。

## 断网时的真实表现

- 可以打开角色、关系、已确认记忆、历史聊天和已下载附件。
- 没有网络时不能假装模型仍可用；发送消息应明确显示“需要联网”或使用已安装的本地模型。
- 恢复联网后先同步元数据和未发送消息，不能自动覆盖本地较新内容，也不能重复创建消息。

## 这一阶段明确不做

- 不修改 `capacitor.config.json` 的服务器地址。
- 不读取或复制线上聊天、私人版本人设和密钥。
- 不安装 SQLite 插件、不打 Android 包、不改生产服务器。
- 不把这份设计当成已经完成的本地 App。
